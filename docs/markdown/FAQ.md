# 常见问题

## 安装和配置

### Q: 如何获取 Bilibili UID？

A: 有以下几种方法：

1. **手机端**：进入个人主页 → 查看资料 → 查看UID
2. **WEB端**：进入个人主页 → 查看地址栏 `/` 后的数字

### Q: 扫码登录失败怎么办？

A: 请检查：

1. 确保使用最新版本的 Bilibili APP
2. 网络连接是否正常
3. 二维码是否已过期（通常 2 分钟过期）
4. 确认扫码账号的 UID 与配置项 `selfId` 完全一致
5. 尝试重新发起登录或刷新二维码

扫码成功后，页面会先显示“二维码已扫描，请在手机上确认登录”，此时还需要在手机端完成确认。登录完成后，Cookie 会保存到本地，后续启动会自动验证缓存。

### Q: 为什么提示“扫码账号和配置项账号不一致，请更换账号”？

A: `selfId` 用于确定当前插件实例登录哪个账号。适配器会将扫码获得的 Cookie UID 与 `selfId` 比对，发现不一致时不会把错误账号当作机器人登录，也不会关闭插件。请更换为与配置项 UID 一致的 Bilibili 账号后重新扫码。

### Q: 插件安装后无法启动？

A: 可能的原因：

1. **依赖问题**：确保 Koishi 版本 >= 4.18.0
2. **配置错误**：检查 UID 是否正确填写
3. **网络问题**：确保能正常访问 Bilibili API
4. **权限问题**：确保 Koishi 有足够的文件读写权限

## 使用问题

### Q: 为什么消息发送/接收有延迟？

A: 这是正常现象，原因包括：

1. **B站限制**：为防止滥用，B站对私信 API 有频率限制
2. **轮询机制**：插件使用轮询方式获取新消息
3. **网络延迟**：网络环境可能影响响应速度

私信轮询间隔由 `pollInterval` 控制，评论通知轮询间隔由 `commentPollInterval` 控制。默认情况下，私信通常约 3 秒轮询一次，评论通知通常约 30 秒轮询一次。

### Q: 如何让机器人响应视频或图文动态评论？

A: 开启 `enableCommentPolling`，然后在视频评论区或图文动态评论区 @ 机器人，或回复与机器人相关的评论。适配器会把评论作为标准 Koishi 消息 Session 下发：

- 视频评论区频道：`video:BV号`
- 图文动态评论区频道：`opus:动态ID`

评论中的 @ 会转换成 Koishi `at` 元素，并保留被提及用户的 UID。@ 后面没有空格时也会尝试根据通知中的提及信息识别。Koishi 产生的回复会回复触发通知对应的评论，而不是发送帖子下的一级评论。

### Q: 头像图片无法显示怎么办？

A: 机器人头像会通过 Koishi 本地反代地址提供给控制台，以处理 Bilibili 图片的请求头限制。普通用户头像仍使用 Bilibili 原始 URL。当前版本不再提供 `avatarBase64` 或 `imageToBase64` 配置；如果仍看到旧配置，请更新插件或重新加载配置 schema。

### Q: 消息发送失败？

A: 可能的原因：

1. **内容被屏蔽**：B站有内容审核机制，敏感内容可能被拦截
2. **频率限制**：发送过于频繁会被限制
3. **登录过期**：需要重新扫码登录
4. **网络问题**：检查网络连接

### Q: 支持发送哪些类型的消息？

A: 目前支持：

- ✅ 纯文本消息
- ✅ 图片消息（需先上传到 B站）
- ❌ 视频消息（暂不支持）
- ❌ 语音消息（暂不支持）
- ❌ 表情包（部分支持）

### Q: 多个插件实例会互相影响吗？

A: 插件支持复用和多配置实例。每个实例根据自己的 `selfId` 保存 Cookie、维护登录状态和前端服务；多个账号可以同时在线。请为每个实例填写对应账号的 UID，不要在不同实例之间共用同一个账号 Cookie。
